# Arbor eval suites

Each `<suite>.eval.json` is a version-pinned suite; `npm run eval:judge -- <suite>` (app/scripts/eval-judge.mts) runs it live and APPENDS one row to `<suite>.results.jsonl` (src/eval/judge.ts). A row carries the judge model, the resolved route model, the prompt versions in force, and per scenario the scores, safe, pass, rationale and — since coach_chat 1.5.1 — `transcript`: the raw route transcript the judge saw, capped at about 6 KB.

The `transcript` field is SYNTHETIC ONLY: the judge runs on the suites' synthetic eval profiles and never on a real family's data, so a results row never holds a real child's words.

**Static-content suites (B-LOOP-14).** `milestone-loop-v1.eval.json` is GENERATED by `app/scripts/build-loop-eval.mts` (`npm run eval:loop:build`) from `app/src/lib/milestoneData.ts` and `app/src/content/practices.ts` — never hand-edit it. Its scenarios are `tier: "static"`: the text under judgement (catalogue title, description, looks-like and the age line; practice do, say, materials) rides in `input.content` in both languages, with the source record it names. `npm run eval:loop` (or `npm run eval:loop -- --ids <scenario, catalogue or practice ids>` for a subset) judges it without a server; the row's `transcript` is that rendered catalogue/practice text (app content, never a family's data), its `rationale` per scenario is what the content builder fixes a failing id from, and the row stamps `contentHashes` (sha256 of the two files). `check:acceptance` WARNS when either file changed after the last generation or the last judged run; the runner refuses a stale suite.

**Voice loop: two tiers (B-PROV-10).** `voice-loop-v1.eval.json` holds a `deterministic` tier and a `live` tier. The deterministic scenarios carry a stubbed model reply, a scripted stream or a screening-down condition; only `app/src/routes/voiceLoopEval.test.ts` (plus `crisisOutput.test.ts` for the crisis-output seeds) can reproduce them, so that file is their gate in CI and they are never judged live. The live scenarios send only what a real parent sends (`parentMessage`, sometimes `recentTurns`), EN + HE. `npm run eval:judge -- voice-loop-v1` judges the live tier only, because the suite declares `runner.deterministicCiGate`. The row lists the skipped ids as `skippedDeterministic` with `skippedReason: "CI gate: app/src/routes/voiceLoopEval.test.ts"`, and `passRate` counts judged scenarios only. Every other suite is judged in full, as before. The 1 Oct row (passRate 0.47) is a structural false red: it sent stubbed deterministic scenarios to a real model. Its genuinely live findings stand: five-sentence replies and a vague Hebrew "consult a professional" referral.
