# AI caller inventory and eligibility audit (B-AIOPS-08)

Every place the server sends family data to an AI provider, what it really carries, and which eligibility decision runs before the provider is chosen. `app/src/ai/callerInventory.test.ts` keeps this table honest: it finds every provider call and AI egress in `app/src/` and fails when one has no row, when a row names a caller that no longer exists, when a route row's consent, crisis-screen, output-screen or model-route column disagrees with the source, or when the "True-request result" column disagrees with what the existing policy (`selectProvider`) decides for the request written in the row.

Audited 28 Oct 2026 on main `5fb5666f`. The existing foundations are real and stay credited: `routeDecisionFor` runs `selectProvider` on every structured-text and stream call (region, no-training, retention; fail closed with `policy_denied`); images filter regions through `imageRegions()`; TTS, book narration and Live each run their own `selectProvider`; the TTS registry fails closed when its adapter is missing.

## Callers

Columns: Capability, Audience and Data classes are what the call really carries (the "true request"). Decision is the eligibility step that runs today. True-request result is what `selectProvider` decides for the true request against the candidates that step uses, in a production configuration (EU text region, the 28 Oct date for Live): `eligible`, `rejects: <reasons>` (the step currently admits the call only because it evaluates a different request), or `no shared decision` (the step is not `selectProvider`). Text in says what free text or voice from a parent or child reaches the call ("none: …" says what comes instead). Crisis screen and Output screen are checked against the route handler's source; a row for a module that is not a route names the route that calls it, and "n/a" says why no screen applies.

## Gaps found (28 Oct 2026)

The test locks the number of `rejects` and `no shared decision` rows at exactly 16: a new gap fails, and a closed gap fails until the lock is lowered in the same change. Closing one means changing the decision, then this table and the lock.

1. **One fixed request for every text caller.** `routeDecisionFor` evaluates `{ audience: "parent", dataClasses: ["child_profile"], locale: "en" }` whatever the caller carries, so the six child-audience routes, photo attachments and vision (`child_image`) and child speech recognition (`child_voice`) are admitted without their real audience or data class being evaluated. The candidates declare no `child` audience and no image or voice class, so passing the true request today would deny those calls. Closing it is a processing decision before it is code: Guy states which provider may process child-audience content, child images and child voice (the DPA and consent basis), then each caller passes its true request.
2. **Images filter by region only.** `imageRegions()` drops non-EU regions in production, but no `selectProvider` decision checks training, retention or audience for image generation, avatar photos or hero poses.
3. **`/tts` declares `public` data.** Coach replies and kid read-aloud can name the child (`child_profile`), which `ttsCandidateFor` does not admit; book narration already declares it correctly.
4. **Book and plan narration depend on `BOOK_TTS_ENDPOINT`.** Their decision is the true request (child audience, `child_profile`), and it is eligible on the EU endpoint. `cloudbuild.prod.yaml` does not set `BOOK_TTS_ENDPOINT`; the default global endpoint is denied in production (fail closed), so name pages work only if the service carries the EU value outside the file (`--update-env-vars` keeps it). Guy confirms the Cloud Run value.
5. **One cross-provider fallback skips the decision.** `modelForGeminiRequest` moves an image-bearing call on a Claude route to the first configured Gemini model without a new `selectProvider` run. It is inactive in production (the chat model is Gemini) and becomes live if GG-3 flips chat to Claude.
6. **Read-aloud declares EU residency but calls the global endpoint, with child names.** `ttsCandidateFor` (`app/src/server/tts.ts:110`) declares its region from `VERTEX_LOCATION` (EU in production), while `synthesizeGoogle` (`app/src/server/tts.ts:76`) posts to `https://texttospeech.googleapis.com`, the global endpoint. The text is coach replies and kid read-aloud, which can carry the child's name. The production EU-only policy therefore admits `/tts` on a declared region that is not where the call goes. Book narration already derives its region from the endpoint it calls. Fix path: (a) call Cloud TTS's EU regional endpoint (the shape `BOOK_TTS_ENDPOINT` already takes) and derive the declared region from it, as `bookTtsCandidate` does; (b) before switching, verify that the two pinned Chirp 3 HD Sulafat voices (en-US, he-IL) are served on that endpoint, from the voices list it returns; (c) Guy decides between the EU endpoint and an explicit, dated exception like Live's, and B-GA-06 reads this gap as well as B-AIOPS-05. Recorded here, not fixed in this change.
7. **Locale is never an eligibility input.** Every shared decision passes `locale: "en"`; no policy uses locale yet.
8. **`POST /plans/phrase` sends parent free text to the model with no crisis screen.** `app/src/server/plans.ts:129-150` takes up to 240 characters (`OWN_WORDS_MAX`) of the parent's own words and puts them in the model prompt; it screens the phrased line afterwards (`screenPhrasedLine`) but never runs `screenForImmediateEscalation` on the input, and no plans component screens on the client. It is live for Guy's family (plan owners default to `ARBOR_FAMILY_EMAILS`, `app/src/config/env.ts:191-198`) and opens to every family as patterns are reviewed. This is a crisis-screen gap, not an eligibility gap (the parent request is eligible), so the eligibility lock above stays 16. A second exact lock covers crisis screens: the rows whose Crisis screen reads "no" while Text in carries a parent's or child's words or voice are exactly `server/plans.ts` (gap 8), `server/childAsr.ts` and `api POST /score-utterance` (child voice; no transcript to screen, and off in production), and `server/planNarration.ts` (stored parent text read aloud); a new row in that set, or one leaving it, fails until the lock moves in the same change; the gap is carried as an open item in `docs/releases/ga05-crisis-release-proof-2026-10-28.md`. Fix (Everyday Plans owner; that code is outside this branch): screen `text` before the model call and return the 409 contract (`escalationCategory`), as the other routes do.
