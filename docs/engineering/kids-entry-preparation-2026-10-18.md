# Deliberate Kids-entry narration preparation — 18 October 2026

Base: `8fad8f1e732f1aa60ef086ad60e8ba8546b39be4`. Scope: B-BOOK-74, not completion of the entire Kids backlog.

## Behavior

The persistent parent button no longer requests named book narration from an effect. The shared parent-owned entry hook prepares narration only after an eligible, deliberate handover has actually opened Kids Mode. A hero-first prompt, cancelled prompt, passive profile refresh or restored Kids session is not permission to start it. Direct world/book doors use the same seam.

The builder is dynamically imported by that interaction. The small EN / HE-m / HE-f folder selector is a pure module; its former export remains compatible. Existing parent-side hero-sheet preparation remains unchanged, as do approved voices, voice models, book assets, proof-child exclusions, parent gates and all visual designs.

Preparation does not delay entry. Owner and selection lifetimes reject stale callbacks and check admission again after credential retrieval, before each new request, retry and local write. The provider-owned selection fence survives a mobile control closing but not a child or account switch. Already-issued server work cannot be recalled by a client fence. Current mounted entries also invalidate changed names, genders, languages and age eligibility.

In-flight jobs are shared per owner/child/configuration. Only confirmed success is remembered, so a refusal, offline attempt or retired job can retry at the next explicit entry. Existing child-local marker keys are retained for erasure coverage, now with ownership in their values. Unowned old markers are ignored; the server still deduplicates stored takes. A book-sheet completion can resume only a still-current deliberate entry intent.
