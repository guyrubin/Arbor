## Real control sequence

`kid-entry-states.mjs` uses ordinary actionable clicks and keyboard/pointer input:

1. Persistent shell door → first child's hero offer → actual descriptor creator
   → creator Cancel → parent-step Cancel, with whole modal removal and focus.
2. Reopen after Cancel without a repeated offer; Escape remains locked; a real
   reload preserves the app-written home lock. The initialization fixture does
   not rewrite an existing lock for this group (all Parent defaults stay intact).
3. Actual three-second hold opens the existing no-PIN parent question. Escape,
   a wrong answer and dismissal remain locked. The visible arithmetic question
   is answered through its real input/submit control to return to the parent.
4. Reopen after a parent reload in the same tab; exit normally; switch to the
   second eligible child through the real switcher; that child gets their own
   offer and enters with the actual Continue with Sprout control.
5. Normal parent return, under-three switch with no door, eligible A→B→A and
   A→under-three→A, then accepted entry for the current eligible child.

Ordinary switches retain the outgoing DOM handle and wait for its retirement,
the settled current route body, current child and visible identity. Rapid ABA
waits for the final body but allows legitimate reuse of A's original node. The
same persistent door node is compared across eligible ABA. Hash alone never
constitutes arrival evidence. Every state checks unchanged invented profiles and
child collection storage; accepted local mode/session writes are observed.

`kid-entry-contract.mjs` lists the exact required assertions for each state.
Missing destination, focus, lock, persistence or action facts cannot be replaced
by a generic passing assertion, a screenshot or a reached flag.

- Only three invented no-hero profiles (4, 3 and 2 years) enter the real demo
  hydrator. Their collections are empty. No real family/account is read.
- No creator Generate or Use control is clicked. No image/save-success callback
  is manufactured. Automatic book-narration POSTs for exactly those three IDs
  receive a labeled local 409 refusal at the API boundary. All other mutations
  are denied, apart from the existing local mock read-like Today/digest requests.

  ABA follows dismissal/parent return; it does **not** claim a pending-modal
  child switch. No forced click, DOM edit, React internal or app callback is used.
- Deferred successful/failed hero persistence, pending-step child retirement,
  stale continuation, same-tick duplicate request and lock→unlock lifetime cases
  remain the reviewed actual-hook evidence. They are not browser-save evidence.
- Parent gate evidence is the existing synthetic no-PIN path only. No PIN is set,
  no real authentication/credential/native Back/production security is tested.
- This minimal fixture stays at the current Kid Mode home destination. Other
  requested view/world targets retain the existing source/hook tests.

## Independent source-review correction

The initial fixture measured the route wrapper itself. Shell intentionally uses
`display: contents` for that wrapper, so the initial readiness test could never
pass in a browser. The corrected observer retains route-root/outgoing identity
and measures its actual `h1`, including the current child's exact bilingual title.
Kid entry measures the real greeting header under `[data-kid-view="home"]`, so
its complete ancestor chain includes the nested home animation; it requires the
current child's rendered greeting rather than just the outer overlay/storage.

Two additional regressions cover the zero-box route wrapper and nested home
animation, with negative controls for missing/duplicate/hidden/empty/detached
content, connected outgoing frames and wrong child identity. Switch-bearing
states now require the visible child-identity assertion in the aggregate.
Post-Escape challenge evidence checks the challenge, persisted open state and
inert parent; wrong-answer evidence checks the actual input's focus.
