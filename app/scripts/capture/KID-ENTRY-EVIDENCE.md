## Real control sequence

`kid-entry-states.mjs` uses ordinary actionable clicks and keyboard/pointer input:

1. Persistent shell door → first child's hero offer → actual descriptor creator
   → creator Cancel → parent-step Cancel, with whole modal removal and focus.
2. Reopen after Cancel without a repeated offer; Escape remains locked; a real
   reload preserves the app-written home lock. The initialization fixture does
   not rewrite an existing lock for this group (all Parent defaults stay intact).
3. Actual three-second hold opens the existing no-PIN parent question. Escape,
   a wrong answer and dismissal remain locked. The visible arithmetic question
   is answered through its real input/submit control to return to the parent.
4. Reopen after a parent reload in the same tab; exit normally; switch to the
   second eligible child through the real switcher; that child gets their own
   offer and enters with the actual Continue with Sprout control.
5. Normal parent return, under-three switch with no door, eligible A→B→A and
   A→under-three→A, then accepted entry for the current eligible child.

Ordinary switches retain the outgoing DOM handle and wait for its retirement,
the settled current route body, current child and visible identity. Rapid ABA
waits for the final body but allows legitimate reuse of A's original node. The
same persistent door node is compared across eligible ABA. Hash alone never
constitutes arrival evidence. Every state compares every invented profile field and unchanged child collection
storage. Only separately validated source-defined visit-stamp transitions on
actually selected synthetic IDs are accepted; local mode/session writes are
observed.

`kid-entry-contract.mjs` lists the exact required assertions for each state.
Missing destination, focus, lock, persistence or action facts cannot be replaced
by a generic passing assertion, a screenshot or a reached flag.
